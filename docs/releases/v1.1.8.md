## 1. Lỗi trong ảnh — chẩn đoán bằng số đo

Ảnh chụp màn hình bắt đầu ở **1920×1080 (DPR 1.5 → viewport CSS 1280×720)** cho
thấy bốn vết lỗi cùng lúc. Cả bốn đều **cùng một nguyên nhân**.

### 1.1 Đo được gì

| Vết lỗi | Vị trí đo được |
| --- | --- |
| Chữ `CHÉO` bị cắt ngang giữa glyph | `y ≈ 371px` ảnh → **247px CSS** |
| Chú lọ mascot mất nửa thân dưới | cùng đường `y ≈ 371px` |
| Panel GAME bị cắt ở đáy | `y ≈ 995px` ảnh → **663px CSS** |
| Dòng `v1.1.7 · AGPL-3.0 …` bị cắt | `y ≥ 998px` ảnh → **665px CSS** |
| Thanh cuộn teal đè lên nền | `x ≥ 1908px` ảnh → **8px CSS** mép phải |

### 1.2 Nguyên nhân — một phép cộng không ai sở hữu

`StartScreen` là **một cột flex** gồm ba phần tử:

```
<div flex flex-col>                       ← 720px
  <div flex-1 overflow-y-auto>  scene      ← nhận 250px, cần ~700px
  <div shrink-0 …>              panel row  ← 415px
  <div shrink-0 …>              ticker     ←  55px
</div>
```

Hai phần tử sau đều `shrink-0` nên **không co lại**. Scene nhận:

```
720 − 415.3 − 54.7 = 250.0px
```

Con số 250.0 này khớp với đường cắt đo được **247.3px** (sai lệch 2.7px do làm tròn
padding). Chữ CHÉO cao hơn 250px nên bị `overflow-y-auto` cắt ngang; chú lọ cũng
vậy — **file SVG không có lỗi**, nó vẫn vẽ đủ `viewBox 0 0 120 140`.

Panel row và ticker thì **cộng dồn vượt hộp**: `250 + 415 + 55 = 720` nhưng panel
cao thực tế 415.3 và ticker 54.7 sau khi cộng thêm padding → cột thành **732px**
trong hộp 720px, nên 12px cuối bị mép dưới cắt.

### 1.3 Cách sửa — đưa chrome ra khỏi luồng

```
<div flex flex-col>                        ← 720px
  <div menu-scene flex-1                     ← nhận 720px (toàn bộ!)
       style="padding-bottom: 338px">        ← tự giữ chỗ cho chrome
  </div>
  <MenuChrome absolute inset-x-0 bottom-0>   ← nổi, không chiếm chỗ
    <hàng panel GAME + INFO>                 ← 268px
    <MenuTicker>                             ←  48px
  </MenuChrome>
</div>
```

Ba thay đổi, mỗi thay đổi xoá một vết lỗi:

1. **`MenuChrome` là `absolute`** → không thể co scene. Scene luôn cao 720px.
2. **Scene `padding-bottom: plan.reserve`** → nội dung không bao giờ chui xuống
   dưới panel, nhưng scene *được phép* cao hết mức.
3. **`.menu-ticker` cao cố định 48px, `overflow: hidden`** → dòng bản quyền nằm
   cùng hàng với marquee thay vì xuống hàng thứ hai.

Kết quả đo lại bằng `planMenuLayout()`:

| Viewport | Reserve | Scene | Bố cục |
| --- | --- | --- | --- |
| 1280×720 (ảnh gốc) | 338px | **382px** | ngang / gọn |
| 1366×768 (laptop) | 338px | 430px | ngang / gọn |
| 1920×1080 (desktop) | 458px | 622px | ngang / đầy đủ |
| 768×1024 (tablet) | 458px | 566px | ngang / đầy đủ |
| 375×667 (điện thoại) | 338px | 329px | **xếp dọc** / gọn |

Scene từ **250px lên 382px** ở đúng kích thước trong ảnh — dư 132px, đủ cho cả
chữ CHÉO lẫn chú lọ.

## 2. Bốn lỗi phụ tìm thấy trong lúc đo

### 2.1 Scrollbar vẽ đè lên tinh vân

`.menu-scene` để lộ track mặc định 8px ở mép phải, và vì nội dung tràn nên thanh
cuộn **teal** của `::-webkit-scrollbar-thumb` được vẽ **lên trên** lớp `nebula-a`.
Trông như một vệt xanh lạ ở rìa phải ảnh.

**Sửa**: ẩn hẳn scrollbar của scene —

```css
.menu-scene {
  scrollbar-width: none;
  -ms-overflow-style: none;
}
.menu-scene::-webkit-scrollbar {
  display: none;
  width: 0;
  height: 0;
}
```

Cuộn vẫn hoạt động (bánh xe, phím, cảm ứng); chỉ thanh chỉ báo là biến mất, và
việc "giữ chỗ" do `padding-bottom` đảm nhiệm thay.

### 2.2 Hai panel đè nhau trên điện thoại

`CornerPanel` là `w-52` (208px) và `sm:w-56` (224px). Hàng ngang cần
`208 + 208 + lề = 456px`, trong khi màn hình điện thoại hẹp nhất là 375px →
hai panel chồng lên nhau và panel INFO che mất nửa panel GAME.

**Sửa**: `planMenuLayout()` trả về `corner: "stacked"` khi `width < 520px`, và
`MenuChrome` render một cột dọc thay vì `justify-between`.

### 2.3 `CHÉO` cao quá khung ở cửa sổ thấp mà rộng

```
clamp(4.6rem, 17vw, 10.5rem)
```

Ở viewport 1920×720 (siêu rộng), `17vw = 326px` → chặn trên `10.5rem = 168px`.
Hai dòng tiêu đề ra **~290px** trong scene chỉ có 250px. Chiều rộng quyết định
cỡ chữ, chiều cao không được xét tới.

**Sửa**: chặn cả hai chiều —

```css
.menu-wordmark {
  font-size: clamp(3.4rem, min(17vw, 20vh), 10.5rem);
}
```

### 2.4 Chiều cao panel phụ thuộc độ dài bản dịch

Mỗi dòng menu cao bằng **bao nhiêu hint cần**. Tiếng Việt
"Âm thanh · nhạc · rung · chuyển động" xuống 3 hàng, tiếng Đức cũng vậy — panel
thành 415px. Tiếng Anh ngắn hơn thì panel thấp hơn. **Bố cục thay đổi theo ngôn ngữ
đang chọn** — một lỗi i18n trá hình thành lỗi layout.

**Sửa**: mỗi dòng khai báo chiều cao cố định bằng custom property, hint bị clamp
2 dòng:

```css
.menu-row      { height: var(--menu-row-h); }        /* 34px, một dòng */
.menu-row-rich { height: var(--menu-row-rich-h); }   /* 54px, có hint      */
.menu-row-hint { -webkit-line-clamp: 2; }
```

Sáu dòng luôn là **268px** hoặc **388px**, ở mọi ngôn ngữ.

it("keeps panel + gap + ticker well under a 720px window", () => {
  expect(CORNER_ROW_RESERVE).toBeLessThan(720 - MIN_SCENE_HEIGHT);

Một dòng này đã đủ bắt lỗi 1.1.7. Phần còn lại khoá những thứ dễ bị lùi:

| Nhóm | Điều được khoá |

| Số học | reserve < 720 − 320; reserve = panel + gap + ticker + lề; panel = 6×row + 5×gap + header + padding + border |
